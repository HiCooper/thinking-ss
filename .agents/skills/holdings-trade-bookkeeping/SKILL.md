# 持仓买卖记账

**适用**：boss 说「我卖/买了 XX，多少份额、什么价位」，要把这笔交易落进看板。
**不适用**：只刷新行情（走 `npm run data:refresh`）；只导入持仓截图（走 `AGENTS.md` §B）。

项目根固定在 `/Users/xueancao/Projects/QoderProjects/thinking-ss`，看板在 `market-dashboard/`。
下面所有命令都在 `market-dashboard/` 下跑，除非注明「仓库根」。

**低频场景下的定位**：交易是低频 + 高语义动作（「卖一半」这类表单表达不了），
所以主路径是**对话记账**，不追求在页面上做交易录入。本 skill 保证每次都走同一口径。

## 一、四份文件，职责不重叠

| 文件 | 谁写 | 存什么 | 入库 |
| --- | --- | --- | --- |
| `holdings.md`（仓库根） | 人/AI 改 | **当前状态**：份额 + 摊薄成本（稳定事实） | ❌ 隐私 |
| `public/holdings.json` | 脚本生成 | 上者的机器可读快照，**别手改** | ❌ 隐私 |
| `public/realized-trades.json` | 人/AI 追加 | **已发生**的卖出流水（append-only） | ❌ 隐私 |
| `public/holdings-history.json` | 脚本追加 | 账户**每日**收益（一天最多一笔） | ❌ 隐私 |
| `public/cash.json` | 人/AI 改 | **账户可用现金**（现金卡 + 今日盈亏率的分母） | ❌ 隐私 |

关键点：`holdings.md` 只存「现在还有多少、成本多少」，**不存交易历史**；
历史分成两条——已实现盈亏进 `realized-trades.json`，账户每日水位进 `holdings-history.json`。
别把交易流水写进 `holdings.md` 的备注里，脚本不读，人也迟早不同步。

**现金（`cash.json`）要跟着买卖一起改**，格式见 §七。它是最容易忘的一份——忘了不报错，
只是现金卡的占比失真（卖了钱进来却还显示旧的余额）。

## 二、卖出 SOP（减仓 / 清仓）

**步骤 0 · 拿到两个数**：卖出份额、卖出价（成交价，不是现价）。boss 没给价格就问，**不要替他猜**。

**步骤 1 · 取当前持仓行**：读 `holdings.md` 明细表，或 `public/holdings.json`（有精确的 `shares` / `cost`）。
校验：卖出份额 ≤ 持仓份额，否则报错停手（可能是说反了、或重复提交）。

**步骤 2 · 算新行**（成本价**不变**，这是券商摊薄成本口径，卖出不改变它）：

```
剩余份额 = 原份额 − 卖出份额
新市值   = 剩余份额 × 现价
新盈亏   = 剩余份额 × (现价 − 原成本)
已实现盈亏 = 卖出份额 × (卖出价 − 原成本) − 费用
卖出净额   = 卖出份额 × 卖出价 − 费用
```

自洽性检查：脚本用 `成本 = (市值 − 盈亏) / 份额` 反推，
用上面的新市值/新盈亏反推回来正好等于原成本 ✅。反推不等就是你算错了。

**「现价」取哪个**：取**成交价**（市价单的成交价就是当时最新价，两者一致）。
减仓后该行要按这个价重估——不重估会让市值仍停在旧快照价上，与份额对不上。
其他行的现价**不要动**（它们各自的市值/盈亏仍是自洽的一对），混时间戳不影响 `--check`。

⚠️ **组内顺序**：明细表是「组内按市值降序」。减仓后该行市值变小，**可能需要与组内下一行交换位置**——
容易漏，改完扫一眼同组。

**步骤 3 · 改 `holdings.md`**：份额、市值、盈亏、盈亏% 四列一起改。
**市值必须等于 `份额 × 现价`**（容差 0.5%），否则 `--check` 直接报错——这是最常踩的坑：只改份额不改市值。
清仓（剩余份额 = 0）→ 删掉该行，并从代码映射表里一并删除。

**步骤 4 · 追加卖出记录**到 `public/realized-trades.json`（文件不存在就新建）：

```json
{ "trades": [
  { "date": "2026-01-15", "code": "159888", "name": "某示例ETF",
    "shares": 1000, "price": 1.500, "cost": 1.450,
    "fee": 0.15,           "day_realized": 49.85 }
] }
```

必填 `date / code / shares / price / cost`；`fee` 可选（默认 0）；
`day_realized` 可选，**填了优先用**（券商 App 显示的当日已实现，比自己算的准，有就填）。

> #### 🚨 `day_realized` 是「当日」口径 —— 填相对**昨收**，不是相对成本
>
> ```
> day_realized = shares × (卖出价 − 昨收价) − fee       ← 正确
> pnl_vs_cost  = shares × (卖出价 − 摊薄成本) − fee     ← 这是累计，别填进 day_realized
> ```
>
> 两者能差一到两个量级。**累计那块不需要你记**：脚本有 `total_cost += shares × cost`，
> 账户 pnl 会自动体现这笔交易从头到尾的盈亏。
>
> 填错的表现：「今日盈亏」凭空多出几千，**且不报错**。实测踩过一次——
> 卖出 8,000 份，当日 −96.00 却填了累计 −4,896.00，
> 页面今日盈亏从 −1,200 变成 −6,000（差 4,800）。
>
> 想留个底就把累计写进 `pnl_vs_cost`（脚本不读，纯记录）。
> 拿不准昨收价就**先不填** —— 不填时脚本会自己按实时昨收算，反而不会错。

> #### 📌 券商的「今日盈亏」是**当日累计**口径（减仓当天最容易对不上账）
>
> 券商按**卖出前**的份额算当日盈亏：卖了的那部分今天也产生了盈亏，会计入当日。
> 所以减仓当天，同一只标的：
>
> ```
> 券商/看板明细行 = 剩余份额 ×(现价−昨收) + 卖出份额 ×(成交价−昨收)   ← 当日累计
> 只看剩余份额    = 剩余份额 ×(现价−昨收)                            ← 正好差一半
> ```
>
> 实测（数字已脱敏）：持仓 16,000 份卖掉 8,000，券商显示 −96，只算剩余份额是 −48——**正好一半**。
> 看板已按当日累计口径实现（`buildCells` 把 `soldPnlByCode` 并进该行，行后会带一个「卖」角标）。
>
> **boss 拿券商数字来对账时，先想是不是这个口径差**——不是数据错了。
⚠️ 所有示例数字都是编造的，真实记录里写真实值，但**永远不要把真实值写进本 skill 或任何入库文件**。

**boss 没给费用时**：按 `fee: 0` 记（ETF 卖出免印花税，佣金通常几元），并在回复里点明
「按零费用记，券商实际扣了佣金告诉我补记」——别自己估一个费率。

**文件不存在**（第一笔卖出）：新建，结构同上，`trades` 数组从这一笔开始。

**步骤 5 · 校验 + 导出**：

```bash
python3 scripts/export_holdings.py --check     # 先校验，不写文件
npm run holdings:export                        # 再写入 public/holdings.json
```

**步骤 5b · 更新现金余额**（`public/cash.json`，与导出同一拍做）：

- 卖出 → `balance += 卖出净额`；买入 → `balance -= 买入份额 × 买入价 + 费用`。
- **以券商 App 的「可用资金」为准**，别信自己算的：佣金、在途资金、未交收的款项都在 App 数字里。
- 同步把 `as_of` 改成今天。忘了这步不报错，只是现金卡的占比失真。

**步骤 6 · 收盘后补快照**（**低于 15:05 不做**，盘中跳过了当日未定稿）：

```bash
npm run holdings:snapshot
```

**为什么步骤 4 不能省**：脚本只在「卖出日 == 快照日」或落在断档区间时，
才把卖出净额计回市值、已实现盈亏计入当日盈亏。**不写这笔记录，卖出当天市值会凭空缩水**
（卖出所得现金没算进去），而且不报错、只是悄悄错。

## 三、买入 SOP（加仓 / 建仓）

```
新份额 = 原份额 + 买入份额
新成本 = (原份额 × 原成本 + 买入份额 × 买入价 + 费用) / 新份额
新市值 = 新份额 × 现价
新盈亏 = 新份额 × (现价 − 新成本)
```

建仓（原来没有）：`新成本 = 买入价 + 费用 / 买入份额`。

新标的还要在 `holdings.md` 的**代码映射表**里加一行 6 位代码。
**代码不许猜**——用新浪 suggest 查（见 §五），猜错代码会显示另一只基金的价格且不报错。

## 四、口径铁律

1. **成本价不用 md 里的「成本」列反算总成本**：那是四舍五入值（如 0.773）。
   权威口径是 `成本 = (市值 − 盈亏) / 份额`——市值和盈亏是行情软件给出的一对自洽数。
2. **改份额必须同步改市值与盈亏**，市值 = 份额 × 现价，容差 0.5%。
3. **卖出不改成本价**，买入才加权摊薄。
4. **`holdings.json` 是生成物**，手改会被下次导出覆盖。
5. **四个文件都不入库**，`git add -f` 强推是红线（历史里清过一次，见 `.gitignore` 注释）。
6. **`day_realized` 记「当日」、不是「累计」**：相对**昨收**而非相对成本，
   填错会让「今日盈亏」虚增几千且**不报错**（实测差过 4,800）。细节与正确公式见 §二 步骤 4。

## 七、现金（`public/cash.json`）

```json
{ "as_of": "2026-01-15", "balance": 12345.67 }
```

看板据此渲染一张**通栏**现金卡（可用现金 / 账户总值 / 占总资产比），排在四张持仓指标卡之前。
**文件不存在 = 还没维护过，卡片不渲染**——正常状态，别为了让它显示去造一个。

> #### ⚠️ 现金不进市值、不进浮动盈亏 —— 刻意的，别"好心"合并
>
> 账户总值若含现金，而总投入（持仓成本）没有对应的**期初本金**科目，多出来的现金会被算成利润：
> 余额里原有的那部分现金会凭空变成盈利，浮亏看起来比实际小。**这不是精度问题，是符号级错误。**
>
> 现金目前只用于两处：
> 1. 现金卡展示（金额、占总资产比、账户总值 = 持仓市值 + 现金）；
> 2. 「今日盈亏率」的**分母**：昨收账户权益 = 当前市值 + 现金 − 今日盈亏
>    （`holdings.ts` 的 `portfolioTotals`）。有 `cash.json` 时用现金，没有才退回卖出净额。
>
> 真要把现金并进口径，得先有「期初本金 + 出入金流水」——那是账本翻转的活，不是改个加法。

**维护时机**：每次买卖后，按券商 App 的「可用资金」更新，与 `npm run holdings:export` 同一拍。
App 数字优先于自己算的（佣金、在途资金都在里面）。
